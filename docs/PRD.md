# 情报驱动 面试备战 · PRD

> 产品名：**情报驱动 面试备战**  
> 一句话：先摸清这场怎么考，再对照简历练；练完只告诉你站住了哪些、还差哪三刀。  
> 线上：https://8.219.189.79.sslip.io/ · 演示：`/interview?demo=1`

## 1. 目标用户

准备**下一场面试**的本科生。可能是公司实习，也可能是学校或科研夏令营；常常一场接一场，去向不定。

一场备战只锁定一个去向 + 一个方向，情报才聚得起来。

## 2. 痛点

不是「没有题可刷」，而是三个不确定：

- **范围**：面经散落在牛客、师兄微信、招生简章里，看完仍说不清这场高频考什么。
- **位置**：简历写了数字和职责/科研经历，没人按这场要求往下追，不知道自己站不站得住。
- **距离**：刷完一套通用题，仍不知道下一刀补哪三条。

ChatGPT 能扮演面试官，但不会先聚合这场的情报，也不会在答不出新事实时停下来给出「只补这 3 个」。

## 3. 核心判断

**焦虑的解药是可核对的事实，不是鼓励。** 进度条必须来自本场真实记录。没有实测支撑的满分会加重焦虑。

**情报是一等公民。** 选拔要求说明「要什么」，情报说明「这场实际怎么问」。没有情报就只对照简历与选拔要求出题；情报对不上这场，不硬画画像。

**商业意图和题目能不能用是两件事。** 引流帖里的真题仍可进考情；看似真诚的帖也可能编造。情报甄别拆成 `verdict` 与 `contentTrust`，不合成一个分数。

**摘录必须能在原文里找到。** 简历、选拔要求、面经的引用在代码里核验，编造的丢掉。

## 4. 主流程

```
这场面试 → 面试情报 → 考情画像 → 针对训练 → 复盘
```

| 步骤 | 用户做什么 | 系统产出 |
|---|---|---|
| 这场面试 | 填去向、方向；粘贴或上传简历与选拔要求（JD / 招生简章 / 考核说明） | 锁定本场材料 |
| 面试情报 | 公开检索、链接抓取，或粘贴 / 上传文件；可标可信度 | 按时间优先的情报列表 |
| 考情画像 | 查看 | 高频考点、要求×简历匹配、近期原题 |
| 针对训练 | 定时长、题量、难度；选完整模拟或情报针对训练 | 按四类题源出的追问 |
| 复盘 | 回看本场 / 历史；可把建议写入简历 | 已验证 / 经不起 / 未覆盖，下一步三刀 |

演示模式预置字节电商交易组材料，不写入历史。`/prepare`、`/analyze` 重定向到 `/interview`。

## 5. 机制

### 5.1 情报

- **公开收集**：按去向、方向自动检索；可贴链接抓取。不登录小红书、知乎，不绕过验证码。
- **手动加入**：粘贴整理稿、上传 PDF/DOCX/TXT/MD。很多真情报不在搜索引擎里。
- 每条带 `source` 与 `trust`（一手 / 公开面经 / 存疑）。条数太少或对不上这场，不进画像。

单篇甄别仍用五维证据（商业意图、细节密度、叙事、账号画像、时效）。每个非中立信号必须带原文摘录。

### 5.2 四类题源

| 标签 | 内部类型 | 含义 |
|---|---|---|
| 面经考点 | `intel_hit` | 这场面经中出现过，非通用题库抽取 |
| 经历已覆盖 | `resume_match` | 选拔要求与简历重合，深挖实际贡献 |
| 经历待核实 | `resume_risk` | 数字或职责偏满，需可核验依据 |
| 要求未覆盖 | `jd_gap` | 选拔要求有明确条目，简历缺少对应经历 |

### 5.3 追问

每题最多两轮。判定的不是「答得好不好」，而是有没有**新增可验证事实**（机制、参数、量级、场景、取舍、本人动作）。复述、套话、「大概/应该是」、说不清则停，记为经不起追问。

### 5.4 难度

出题与追问都带当前档，三档角度不同：

| 档 | 问法 |
|---|---|
| 舒适 | 先问做过的部分和成功路径 |
| 常规 | 机制问清后再追一层边界 |
| 加压 | 开场对质失败路径和数字口径 |

### 5.5 复盘

不看平均分当结论。看哪几个点站住、哪几个被追回来、哪几个还没问到。下一步只给三条。简历修改建议可连续写入本场材料，再练一轮按新简历出题。

## 6. 刻意不做

- 账号登录：评委打开即用
- 语音 / 视频面试：文字闭环优先
- 浏览器插件：评委必须能直接访问 Web
- 扫描件 OCR：文字版 PDF/DOCX 可解析；纯图请先转文字
- 爬取小红书 / 知乎：合规与风控

## 7. 迭代（相对最初方案）

最初做「面经打假 + 考纲自评地图」。学生更急的是下一场怎么答，主路径改为简历 × 选拔要求 × 情报的深挖训练；考纲收成考情画像，不再让用户逐点打钩。

过程中改过：简历输入框 `key` 导致打不了字；题源从内部词改成书面四词；用户从「只面公司」扩到夏令营；难度三档提示过弱导致出题几乎一样，后改为出题与追问都带难度。

## 8. 技术与部署

- Next.js 16 App Router + TypeScript + Tailwind CSS 4
- DeepSeek（`deepseek-chat`），判定类低温；摘录代码核验
- 练习与复盘在浏览器 localStorage，不上传服务器
- 香港轻量服务器 + Caddy HTTPS；项目目录 `/opt/ai-interviewer`，服务 `ai-interviewer`
- 评委两把 SSH 公钥已写入服务器

## 9. 合规

- 运行时不向小红书、知乎登录或绕过验证码；自动检索只读公开页
- 作者标识入库前哈希；不存昵称头像
- 示例与演示数据为虚构，不含真实个人信息

## 10. 若再有一周

- 多场复盘纵向对比：同一考点隔几天再练，看是站住了还是又被追回来
- 情报按「夏令营 / 实验室 / 公司组」分开权重
- 从面经生成有信息量的反问，而不是「请问团队氛围如何」
- 增加实习面试时可能会出现的无领导小组讨论，ai分饰多角营造讨论氛围，留给用户参与空间
- 多模态，完善音频、视频的互动环节，让面试更接近真实情况
- 在合规爬取的基础上进一步优化筛选信息的质量，减少盐选广告干扰项
